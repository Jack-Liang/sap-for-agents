What happens next

        
    
            
  1. Your assistant asks the gateway which fields are needed, then interviews you: SAP host, system number, client, user, password, and a short system name.
    2. 
            
  2. It submits them to the gateway — which opens a real test connection first. Nothing is saved if the connection fails, so you never end up with a broken config.
    3. 
            
  3. Once the test passes the system is live without a restart, and this page turns into the systems console above.
    4. 
        

        
Tip: passwords accept a ${ENV_VAR} indirection, keeping the secret in your environment and out of the chat log.

    


    
    

        

            Prefer the API or doing it by hand? (click to expand)
            

                
Everything this page does is plain HTTP (writes are allowed from this machine by default):

                
curl -X POST   http://127.0.0.1:3000/api/setup/system          -H "Content-Type: application/json" -d '{"name":"a4h",…}'
curl           http://127.0.0.1:3000/api/setup/system/a4h      # read one (passwd masked)
curl -X PUT    http://127.0.0.1:3000/api/setup/system/a4h      -H "Content-Type: application/json" -d '{"passwd":"new"}'   # partial update
curl -X DELETE http://127.0.0.1:3000/api/setup/system/a4h      # remove (last one needs ?force=true)
curl -X PUT    http://127.0.0.1:3000/api/setup/default         -H "Content-Type: application/json" -d '{"name":"a4h"}'     # switch default

                
Or edit sap_systems.toml by hand and restart the gateway.
